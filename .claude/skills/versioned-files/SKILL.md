# 버전 파일 저장 규칙

사용자에게 주는 결과물 파일은 **덮어쓰지 않고, 고칠 때마다 새 버전 파일**로 저장한다.

## 1. 파일명

```
<문서이름>_v.<메이저>.<마이너>.<패치>(<YY.MM.DD>).<확장자>
```

- 예: `AI특강_기획안_v.1.0.0(26.10.04).md`, `AI특강_슬라이드_v.1.2.0(26.10.05).html`
- 날짜는 **저장하는 날(한국 시간)** 기준 `YY.MM.DD`
- 문서이름은 한글 가능, 공백 대신 `_`

## 2. 버전 올리는 기준

| 자리 | 언제 | 예 |
|---|---|---|
| 메이저 `X.0.0` | 구성·방향을 전면 개편 | 대상·목적이 바뀜, 목차를 새로 짬 |
| 마이너 `1.X.0` | 내용 추가·삭제·교체 | 소재 추가, 영상 교체, 화면 추가 |
| 패치 `1.0.X` | 오타·표현·숫자 등 작은 수정 | 문구 다듬기, 링크 수정 |

- 처음 만드는 파일은 `v.1.0.0`
- 날짜가 바뀌어도 버전 규칙은 그대로 이어서 올린다 (날짜만 새 날짜)

## 3. 저장 방법

1. 기존 최신 파일을 복사해 **새 파일명**으로 만든 뒤 고친다. **이전 버전 파일은 지우거나 덮어쓰지 않는다.**
2. 사용자가 직접 고친 내용이 있으면 그 최신 파일을 기준으로 이어서 고친다.
3. 저장소(git)에서 작업 중이면 커밋 메시지 첫 줄에 새 파일명(버전)을 쓴다.

## 4. 문서 안에 변경 이력 넣기 (필수)

### Markdown(.md)
문서 맨 위 정보 표 바로 아래에 **`## 변경 이력`** 을 두고, **최신 버전이 위**에 오도록 누적한다. 이전 버전의 이력도 지우지 않고 계속 남긴다.

```markdown
## 변경 이력
| 버전 | 날짜 | 수정 내용 |
|---|---|---|
| v.1.2.0 | 26.10.05 | ① 영상 V1·V2 교체 ② 화면 27 삭제 ③ 부록 C 정리 |
| v.1.1.0 | 26.10.04 | 화면별 상세 구성 추가 |
| v.1.0.0 | 26.10.04 | 최초 작성 |
```

- 수정 내용은 **무엇을 → 어떻게** 바꿨는지 구체적으로 (화면 번호·섹션명 포함)
- 사용자가 요청한 내용과 내가 판단해 함께 고친 내용을 모두 적는다

### HTML(.html)
- `<head>` 안 맨 위에 HTML 주석으로 같은 변경 이력 표를 넣는다.
- 화면에 보이게 할 필요는 없다.

### 그 밖의 파일 (xlsx, pptx, docx 등)
- 문서 안에 "변경 이력" 시트/페이지/표를 둔다. 넣을 수 없는 형식이면 같은 이름의 `_변경이력.md`를 함께 만든다.

## 5. 답변할 때

- 저장한 **새 파일명**과 **이번에 바꾼 내용 요약**을 사용자에게 알려준다.
