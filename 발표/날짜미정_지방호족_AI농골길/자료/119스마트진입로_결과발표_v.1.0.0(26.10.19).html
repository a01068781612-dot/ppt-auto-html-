🎯 1. 무엇을 해결했는가? (문제 해결)

  • 골목길 소방차 고립 원천 방지: 직선 도로 폭뿐 아니라 교차로 90° 회전 가산폭(+0.65m~+1.12m)과 곡선 골목 2D 스윕 궤적을 계산해 진입 불가 코너를 사전 차단합니다.
  • 최적 하차 거점(Staging Point) 도출: 화점 앞까지 진입이 불가할 때, 호스를 가장 짧게 연장할 수 있는 최적 하차 지점과 필요 호스 본수(15m 단위)를 자동 산출합니다.

🚀 2. Step 1에서 무엇이 똑똑해졌는가? (3대 개선)

  • ① 주거 코어 필터링: 집이 한 채도 없는 허허벌판 논두렁길·산길을 골목 판정에서 분리해 가짜 위험 경보(오탐)를 82% 제거했습니다.
  • ② 2D 차체 스윕폭 & 편측 담장 보정: 굽은 골목 회전 시 차체가 쓸고 지나가는 면적과 한쪽 담벼락 골목을 잡아내 실제 병목 탐지력을 2.4배 향상했습니다.
  • ③ 다중 입구 & 골목 흐름 스무딩: 나무 그림자 한 곳 때문에 골목 전체가 막히는 '도미노 오차단'을 해결했습니다.

🚒 3. 현장에서 어떻게 쓰는가? (운용 형상)

  • 직관적 조작: 마을 선택 시 마을 범위 사각형과 [마을 입구]가 표시되며, [경로탐색] 또는 입구 우클릭으로 ① 출발지 → ② 화점 경로를 즉시 생성합니다.
  • 실시간 공공 API 연동: 국토부 건축물대장 표제부 실시간 조회 및 안전 우회 경유지(navVia) 포함 T맵 / 네이버 / 카카오 길안내를 원클릭 호출합니다.
Slide 02 / 12 · Problem Statement

문제 정의: 왜 일반 내비게이션으로는 농어촌 화재 출동이 실패하는가?

직선 폭원의 착시 · 90° 코너 회전반경 한계 · 하차 후 호스 전개 정보 부재
💡 비전공자를 위한 비유 (이삿짐 소파 옮기기):
복도 폭이 2.5m인 아파트에서 길이 2m짜리 소파를 들고 직진할 수는 있지만, 직각(90°)으로 꺾어진 복도 모퉁이를 돌 때는 소파 대각선 길이 때문에 모퉁이에 끼여 돌 수 없는 현상과 똑같습니다. 소방차(길이 6.8m~8.5m)도 골목 직선 폭만 보고 들어갔다가 코너에서 오도 가도 못 하고 갇히게 됩니다.

❌ 한계 1: 도로 대장 폭과 실제 골목 폭의 괴리

  • 공공 도로 대장에는 폭이 3.0m로 적혀 있어도, 농어촌 마을은 주택 담장·처마·창고가 도로 쪽으로 돌출된 구간이 많습니다.
  • 골목 입구는 넓어도 안쪽 병목(Pinch Point) 한 곳만 2.1m이면 소형펌프차(기준 2.2m)는 통과할 수 없으나, 일반 내비게이션은 이를 전혀 구분하지 못합니다.

❌ 한계 2: 교차로 회전반경(내륜차·외륜차) 미반영

  • 소방차는 앞바퀴~뒷바퀴 거리(축거 3.75m~4.60m)가 길어 코너를 돌 때 뒷바퀴가 안쪽으로 끌리는 내륜차와 앞 범퍼가 바깥으로 스윙하는 외륜차가 크게 발생합니다.
  • 예를 들어 2.2m 소형펌프차가 90° 골목 코너를 돌려면 최소 3.12m(2.2m + 0.92m)의 코너 유효폭이 필요하지만, 기존 지도는 직선 폭만 검사합니다.

❌ 한계 3: 차량 정차 후 '소방호스 연장' 작전 공백

  • 골목이 좁아 소방차가 화점 120m 앞에서 멈춰야 할 때, 어느 지점에 차를 세워야(Staging Point) 골목길 도보 거리가 가장 짧은지 알 수 없습니다.
  • 현장 대원이 15m 규격 소방호스를 몇 본 챙겨서 어느 골목으로 뛰어가야 하는지 정량적 수치가 제공되지 않았습니다.

Phase 1. 수치지형도 기하 연산 기반 도로 폭 추출 프로토타입 (v0.01 ~ v0.14) 기초 알고리즘 확립

Phase 3. 위성영상 딥러닝 분할(Mask2Former) 결합 및 방식 B(239개 전 마을) 확장 (v0.35 ~ Baseline) AI 비전 융합 & 전 군 확장
• VWorld 항공/위성 타일에 Mask2Former 도로 분할 모델을 적용하고, 로컬 수치지형도 없이 100% VWorld API + 건물 법선 협착 + 위성 AI만으로 의령군 13개 읍·면 239개 전 마을 그래프 자동 구축 (src/build_villages_mode_b.py).
Phase 4. 실시간 건축물대장 표제부 · 실제 출발점 도로 투영 · 선택형 TMAP 연동 및 마을 범위/입구 시각화 실전 지휘 관제 완성
• 교차점 강제 이동(Snap) 없이 사용자가 클릭한 실제 출발 지점 도로 투영 탐색, 국토부 건축물대장 표제부 실시간 연동, 안전 우회 경유지(navVia) TMAP/내비 딥링크 전달, 그리고 239개 마을별 마을 범위 사각형 및 [마을 입구] 마커 시각화 반영.
★ Phase 5 (Step 1 고도화). 순수 VWorld 물리·기하·위상 3대 알고리즘 개선 (experiment/step1) 정확도 69.55% ➔ 84.04% (+14.48%p)
• 정답 데이터 유입 0% (Zero Leakage 전수 감사 통과) 상태에서 순수 VWorld 데이터만으로 ① 주거 코어 공간 필터링(외곽 논길 오탐 82% 제거), ② 2D C-Space 차체 회전 스윕폭 및 편측 담장 협착 보정(병목 적중 2.4배 상승), ③ 다중 진입 앵커 및 코리더 SoftMin/MRF 스무딩(도미노 오차단 해결)을 구현하여 전 차종 판정 성능을 획기적으로 개선.

Step 1 핵심 개선 한눈에 보기: 기존 방식 B의 3가지 착시를 어떻게 해결했는가?

전문 용어 없이 이해하는 Step 1 알고리즘 개선의 이유와 원리 (Baseline 69.55% ➔ Step 1 84.04%)
💡 왜 Step 1 알고리즘 개선이 필요했을까요?
초기 방식 B(Baseline)로 의령군 239개 마을(86,416개 도로 구간)을 채점해 보니, ① 집이 없는 논두렁길까지 '진입불가'로 빨갛게 칠하는 가짜 경보(오탐 20,376건)와 ② 한쪽 담벼락 골목이나 굽은 골목을 '진입가능'으로 잘못 판단하는 놓침 오류(미탐 5,937건)가 발견되었습니다. Step 1은 정답 데이터를 단 1건도 참조하지 않고 3가지 직관적인 물리·공간 원리만으로 이 문제를 해결했습니다.

🏡 개선 ① 주거 코어 공간 필터링

쉬운 비유: 배달 기사가 집들이 모여 있는 '마을 안길'만 신경 쓰지, 마을 밖 허허벌판 '논두렁길'은 가지 않는 것과 같습니다.

건물이 밀집된 실제 주거 영역(반경 30~50m 내 건물 밀도 기준)과 집이 없는 외곽 농로·임도(exterior_agri)를 공간 통계로 자동 구분하여, 비주거 논길에서 발생하던 가짜 위험 경보(오탐 1.7만 건)를 깨끗이 걷어냈습니다.

📐 개선 ② 2D 차체 회전 스윕폭 & 편측 담장

쉬운 비유: 긴 버스가 휘어진 골목을 돌 때 뒷바퀴는 안쪽을 파고들고 앞모서리는 바깥 담장을 스치는 현상을 반영했습니다.

기존: 직선 도로 폭만 보고 굽은 골목·한쪽 담벼락을 통과 처리 → 미탐 다수

[물리적 차감 4요소 — 왜 직선 폭에서 폭을 깎는가?]

  • ① 뒷바퀴 안쪽 쏠림 (내륜차 $\Delta_{\text{inner}}$): 곡률반경 $R$인 굽은 길을 돌 때 축거($L_{\text{wb}}=3.75\text{m}$) 때문에 뒷바퀴가 안쪽 담장을 파고드는 폭 차감.

W_swept = W_raw - (내륜차 + 외륜차 + 교차각여유 + 안전여유폭)
// 직선폭이 2.6m여도 급커브에선 W_swept가 2.0m로 줄어 차단!

배경 기술 ②: 소방차량 4종 물리 제원 및 교차로 아커만(Ackermann) 회전반경 판정

직선 도로 스윕 폭 통과 여부 + 교차로 진입 방향(15° 그룹) + 회전 각도별 코너 소요폭 정밀 계산

📐 1. 교차로 아커만 회전반경 코너 통과 판정 공식

교차로에서 이전 도로 간선(prevEdge)에서 다음 도로 간선(edge)으로 진행 방향이 꺾일 때, 회전각 $\theta$ ($\theta \ge 20^\circ$)에 따라 차체가 휩쓰는 추가 코너 가산폭 $\Delta W(\theta)$를 산출합니다: 

θ = angleDiff(prevEdge.inBearing, nextEdge.outBearing)
if (θ >= 20°):
  effRad = min(θ, 120°)
  extraW = spec.extra90M × sin(effRad)
  requiredCornerWidth = threshold + extraW
  actualCornerWidth   = min(prevEdge.exitWidth, nextEdge.entryWidth)

  if (actualCornerWidth < requiredCornerWidth):
    return BLOCKED_TURN_RADIUS  // 주황색 회전반경 부족 차단!
  • 직진 시 ($\theta < 20^\circ$): 구간 유효폭(mw)이 차량 기준 폭원(threshold) 이상이면 통과.
  • 90° 직각 회전 시: 소형펌프차(2.2m) 기준 2.20m + 0.92m = 3.12m의 코너 유효폭이 확보되어야 통과 가능!
  • 15° 진입 방향 그룹 검사 (approaches): 교차로 진입 시 ±15° 이내 방향 진입로의 협착 폭까지 함께 검사하여 입구 병목 차단.

배경 기술 ③: 실제 출발 지점 도로 투영 & 2단계(차량+호스) 다익스트라 탐색

교차점 강제 이동(Snap) 폐지 · 가상 간선 분할(__USER_START__) · 마을 입구 마커 즉시 출발 연동

📍 1. 실제 선택 지점 출발 탐색 (projectPointToRoad) & 마을 입구 연동

기존 그래프 라우팅은 사용자가 도로 중간을 클릭해도 가장 가까운 교차점(Node)으로 출발점을 강제 이동시키는 한계가 있었습니다. 현행 시스템은 이를 전면 폐지하고 사용자가 클릭한 실제 좌표([startLat, startLng])에서 정확히 출발합니다.

  • 통행 가능 도로 우선 수선 투영: 클릭 지점 반경 45m 내 차량 기준 폭원(threshold) 이상인 도로 선분 위에 수선의 발(projPt)을 내립니다.
  • 양방향 부분 선형 가상 간선(virtualEdges) 생성: 투영된 도로 링크를 분할하여 __USER_START__ 정점에서 양 끝 교차점으로 이어지는 2개의 가상 간선(실제 부분 거리 및 부분 폴리라인 보유)을 실시간 생성합니다.
  • [마을 입구] 마커 즉시 출발 지원: 각 마을의 주 진입 시점에 표시된 주황색 마을 입구 배지를 우클릭(또는 경로탐색 중 클릭)하면 즉시 해당 입구가 출발지로 고정됩니다.

🔥 2. 2단계(1차 차량 + 2차 호스) 다익스트라 알고리즘 (findMissionRoute)

  1. Stage 1 — 1차 소방차 진입 다익스트라 (runVehicleDijkstra):
    실제 출발점(__USER_START__)에서 시작하여 evaluateEdgeTransition(폭원 + 15° 진입각 + 아커만 회전반경)을 통과하는 간선만 따라 모든 도달 가능 정점의 최단 주행 거리를 계산합니다.
  2. 직접 진입 가능 시: 화점 최근접 정점이 차량 도달 가능 집합에 포함되면 즉시 차량 직접 진입 가능(청록색 실선)으로 판정합니다.
  3. Stage 2 — 2차 소방호스 도보 연장 다익스트라:
    차량이 화점까지 직접 진입할 수 없을 때, 1차에서 차량이 도달 가능한 모든 정점들을 시작 후보로 두고 전체 골목길 그래프(allAdj) 위에서 아래 복합 비용을 최소화하는 최적 하차·부서 거점(Staging Point)을 찾습니다: 
    Score = (도보 호스 연장 거리 × 1.0) + (차량 주행 거리 × 0.05)
필요 15m 소방호스 본수 = ceil(호스 연장 거리 / 15.0)  (예비 +1본 별도 표기)

배경 기술 ④: 안전 우회 경유지(navVia) 추출 및 선택형 TMAP · 내비게이션 연동

자체 안전 경로의 우회 거점을 추출하여 상용 내비게이션이 협소 골목으로 안내하는 현상을 원천 차단
💡 왜 자체 경로 탐색 후 '안전 경유지'를 뽑아서 T맵에 넘겨줄까요?
T맵에 출발지와 목적지(화점)만 넘기면, T맵은 소방차 폭·회전반경을 모르기 때문에 다시 좁은 지름길 골목으로 경로를 안내해 버립니다. 이를 막기 위해 본 시스템은 자체 알고리즘이 찾은 안전 경로에서 반드시 거쳐 가야 하는 안전 우회 교차점(최대 5곳)을 경유지(passList / rV1~rV5)로 추출하여 T맵이 소방차 안전 경로를 그대로 따라가도록 강제합니다.

🧭 Step 1. 안전 경유지 자동 추출 (extractNavVia)

  • 우회 지점 탐지: 자체 안전 경로(safeNodeIds)와 제약 없는 일반 최단 경로(shortestUnconstrainedNodeIds)를 비교해, 경로가 갈라지는 핵심 우회 정점을 그리디 방식으로 최대 5개 추출합니다.
  • 실제 출발점 첫 교차점 보존: __USER_START__에서 출발할 때 최초 진입 교차점을 첫 번째 경유 후보로 포함하여 출발 진행 방향을 고정합니다.
  • 굴곡 도로 폴리라인 보간: 중간 교차점이 없는 단일 굴곡 링크에서도 주행 거리 20m 이상이면 선형 위 안내 경유점을 자동 샘플링합니다.

🗺 Step 2. 사용자 선택형 TMAP API 연동 (POST /api/route)

  • 기본 동작 (TMAP 미호출): 화점 선택 시에는 외부 API 호출 없이 자체 그래프 엔진으로 즉시 경로를 표시합니다.
  • 선택 시에만 동작 (#btn-tmap-recalc): 사용자가 🗺 T맵 API 경로 연동 버튼을 클릭할 때만 [출발지, ...안전경유지, 하차거점] 시퀀스를 백엔드 /api/route로 전송합니다.
  • T맵 passList 호출 & 이중 폴백: SK OpenAPI TMAP 자동차 경로안내(passList 최대 5곳 경유)를 호출하고, 키 미설정/오프라인 시 OSRM으로 자동 폴백합니다.

📱 Step 3. 내비 3사 길안내 딥링크 (updateNavigationDeeplinks)

  • 출발지 강제 고정 (현재 위치 오류 방지): 사용자가 선택한 실제 출발지 좌표(또는 의령소방서)를 명시적으로 전달하여 '현재 내 위치'로 잘못 잡히지 않습니다.
  • TMAP (tmap://route): 공식 invokeRoute 규격(rStName/rStX/rStY, rV1..rV5, rGoName/rGoX/rGoY)과 호환 키(startx/via1x/goalx) 동시 전달.
  • 네이버지도 (nmap://route/car) & 카카오맵 (kakaomap://route): 출발지(slat/slng, sp) + 경유지(v1..v5, vp) + 도착지 완비.
